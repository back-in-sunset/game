# 产品需求文档（PRD）v0.2

**项目名称**：Game 社交化游戏后端  
**文档版本**：v0.2  
**更新时间**：2026-05-09（基于实际代码状态修订）  
**文档目标**：明确当前阶段产品边界、功能目标和版本规划，不承担技术实现细节说明。  

---

## 1. 项目定位

本项目是一个面向多人游戏场景的后端基础平台，当前阶段聚焦“游戏社交底座”建设，而不是一次性实现完整社区和战斗体系。

当前产品方向包括：

- 用户账号与鉴权
- 评论与互动能力
- IM 基础通信能力
- 游戏公共服务能力
- 本地开发与调试环境支持

本版 PRD 原则：

1. 只描述当前阶段真实要交付的产品能力。  
2. 不把未来可能做的技术方案写成当前承诺。  
3. 优先支撑后续 `user/comment/im` 三类服务的持续迭代。  

---

## 2. 本阶段目标

### 2.1 总目标

交付一个可本地部署、具备基础业务闭环、可继续扩展的游戏后端最小版本。

### 2.2 阶段目标

- 完成用户服务最小闭环：注册、登录、鉴权、查询本人信息
- 完成评论服务最小闭环：发评论、查评论、删评论、评论列表
- 完成 IM 服务基础闭环：WebSocket 长连接、JWT 鉴权、单聊消息收发、离线消息存储
- 完成好友服务基础闭环：添加、删除、查询、在线状态
- 完成 VDA 语音信令服务基础闭环：LiveKit 集成、token 签发
- 完成前端 monorepo 基础架构：Web 控制台 + Mobile 壳工程
- 支持开发环境按需启动依赖中间件

### 2.3 非目标

以下内容不属于当前阶段交付范围：

- 社区动态 feed
- 群聊、频道、会话体系
- 匹配系统、战斗房间、帧同步
- 统一网关接入
- 事件总线驱动的复杂异步架构
- 租户/项目管理后台
- 计费与配额系统
- 语音通话前端完整 UI（服务端信令已就绪）

---

## 3. 用户角色

### 3.1 普通用户

可注册、登录、查看自己的用户信息，并对业务对象发表评论。

### 3.2 运营/管理员

本阶段不单独交付运营后台，但评论审核、屏蔽、置顶等能力需要在产品范围内预留。

### 3.3 开发者

当前阶段开发者也是核心使用者之一，因此产品层面对“可启动、可调试、可联调”有明确要求。

## 4. 功能范围

## 4.1 用户服务

### 4.1.1 注册

功能说明：

- 用户通过手机号、密码、昵称注册
- 服务保存基础用户信息

输入要求：

- `name` 必填
- `mobile` 必填
- `password` 必填

输出要求：

- 返回用户基础信息：`id/name/gender/mobile`

验收标准：

- 注册成功后可立即用于登录
- 同手机号不可重复注册

### 4.1.2 登录

功能说明：

- 用户通过手机号、密码登录
- 登录成功后返回访问令牌

输入要求：

- `mobile` 必填
- `password` 必填

输出要求：

- `accessToken`
- `accessExpire`

验收标准：

- 正确账号密码可登录
- 错误密码不可登录
- 登录态可用于访问受保护接口

### 4.1.3 用户信息

功能说明：

- 已登录用户查询自己的用户信息

输出要求：

- `id/name/gender/mobile`

验收标准：

- 未登录不可访问
- 用户不能读取其他用户的信息

### 4.1.4 本阶段不做

- 修改资料
- 头像上传
- 刷新 token
- 账号封禁/注销

---

## 4.2 评论服务

### 4.2.1 新增评论

功能说明：

- 用户对指定业务对象发表评论
- 支持根评论和回复评论字段

输入要求：

- `obj_id` 必填
- `obj_type` 必填
- `member_id` 必填
- `message` 必填

输出要求：

- 返回评论基础信息

验收标准：

- 评论写入后能在详情和列表中查询到

### 4.2.2 查询评论详情

功能说明：

- 按对象和评论 ID 查询单条评论

输入要求：

- `obj_id` 必填
- `comment_id` 必填

验收标准：

- 能返回评论基础内容、作者、时间、统计字段

### 4.2.3 删除评论

功能说明：

- 用户删除自己的评论

输入要求：

- `obj_id` 必填
- `comment_id` 必填
- `member_id` 必填

验收标准：

- 删除后评论不应以正常状态出现在查询结果中

### 4.2.4 评论列表

功能说明：

- 按对象维度获取评论列表
- 支持按时间或点赞数排序

输入要求：

- `obj_id` 必填
- `obj_type` 必填

验收标准：

- 能正确返回分页评论结果

### 4.2.5 预留能力

以下功能属于下一阶段重点，但本阶段不要求完整交付：

- 点赞评论
- 取消点赞
- 屏蔽评论
- 取消屏蔽
- 置顶评论
- 取消置顶
- 评论审核

## 4.3 IM 服务

### 4.3.1 当前定位

IM 服务已形成完整基础闭环：WebSocket 长连接 + JWT 鉴权 + 二进制帧协议 + 单聊消息路由 + MySQL 持久化 + Redis 会话管理。

### 4.3.2 已实现能力

- WebSocket 接入（端口 8082），支持二进制帧协议（16 字节大端 header + JSON body）
- JWT RS256 鉴权（platform API 签发公钥验证）
- 单聊消息完整链路：发送 → 路由 → 在线投递 / 离线存储
- TCP 接入（端口 8091），用于服务间通信
- 会话管理（bucket + ring 分片，心跳保活 30s）
- etcd 服务发现注册
- 离线消息补发（上线后拉取未读消息）
- 操作码：OpAuth(7) / OpAuthReply(8) / OpHeartbeat(2) / OpServerPush(4) / OpError(6)

### 4.3.3 前端状态

- Web 前端已接入 IM WebSocket，可实时收发消息
- Dashboard 页面展示会话列表和消息面板
- 消息 UI 组件库（`@game/ui`）支持消息气泡、会话卡片

### 4.3.4 本阶段缺口

- 群聊/频道
- 已读回执
- 消息搜索
- 多媒体消息（图片/语音片段）
- TCP 客户端 SDK

---

## 4.4 好友服务

### 4.4.1 当前定位

好友服务已实现基础 CRUD，通过 go-zero RPC 暴露接口，前端通过 HTTP API 调用。

### 4.4.2 已实现能力

- 添加好友（发送请求 → 同意/拒绝）
- 删除好友
- 好友列表查询
- 好友在线状态（通过 IM presence 推送）

### 4.4.3 本阶段缺口

- 好友分组/标签
- 黑名单
- 好友备注
- 前端好友页面完整 UI（API 层已就绪）

---

## 4.5 VDA 语音服务

### 4.5.1 当前定位

VDA（Voice Driving Agent）服务负责语音通话的信令层，集成 LiveKit 作为 WebRTC 媒体传输层。

### 4.5.2 已实现能力

- LiveKit 服务端集成（Docker 部署，端口 7880）
- VDA gRPC 服务（端口 9101）：token 签发、房间管理
- 语音信令协议定义（call_invite / call_accept / call_reject / call_end）
- 服务端通话状态管理

### 4.5.3 本阶段缺口

- 语音分钟数计费
- 通话录制
- 视频通话

---

## 4.6 前端 Monorepo

### 4.6.1 当前定位

`frontend/` 为 pnpm monorepo，包含 Web SPA 和 Mobile 壳工程，以及 4 个共享包。

### 4.6.2 已实现能力

- `apps/web`：Vite + React SPA，Dashboard / Chat / Voice / Friends / Settings 页面骨架
- `apps/mobile`：Expo + React Native 壳工程
- `packages/api`：IM 协议编解码、HTTP API 客户端
- `packages/ui`：共享 UI 组件（Card、StatusRow、ChatBubble 等）
- `packages/config`：共享配置
- `packages/shared`：共享类型和工具
- Zustand 状态管理（auth / im / settings stores）
- React Router v7 路由

### 4.6.3 本阶段缺口

- Mobile 端功能实现（当前为占位页面）
- E2E 测试
- 组件测试
- Storybook 文档

---

## 4.7 开发环境能力

本阶段产品层面对开发环境有以下要求：

- 可本地部署核心依赖
- 支持按需组合中间件
- 不要求开发者每次起全量组件

## 5. 非功能要求

### 5.1 可用性

- 核心依赖可以在本地独立启动
- 核心服务具备最小可运行闭环

### 5.2 可维护性

- 服务边界清晰
- 接口行为稳定
- 文档与实现状态一致

### 5.3 可测试性

- 用户与评论服务需要具备最小联调能力
- 核心主链路需要可验证

---

## 6. 当前版本交付范围

本阶段已交付项：

- 用户注册、登录、用户信息、JWT 鉴权
- 评论新增、详情、删除、列表
- IM 服务完整基础闭环（WebSocket/TSL 鉴权/单聊/离线消息）
- 好友服务基础 CRUD（RPC 层 + HTTP API）
- VDA 语音信令服务（LiveKit 集成 + gRPC token 签发）
- 前端 monorepo（Web SPA + Mobile 壳 + 4 共享包）
- 可组合的本地中间件部署方式（Docker Compose 按需启动）

本阶段不承诺交付：

- 动态/攻略系统
- 群聊/频道
- 语音通话前端完整 UI
- 游戏对战核心逻辑
- 租户/权限/计费平台后台

## 7. 版本规划

### v0.2 当前版本（已基本完成）

实际交付超出原计划：
- user/comment 基础闭环按计划完成
- IM 从"代码骨架"演进为完整基础闭环（超出预期）
- 新增好友服务（原计划 v0.4）
- 新增 VDA 语音信令服务（原计划未覆盖）
- 新增前端 monorepo（原计划未覆盖）

### v0.3 当前版本

已完成：
- 前端 LiveKit 客户端集成，端到端语音通话（DemoPage + DemoRoomPage）
- 好友前端完整 UI（FriendsPage 添加/删除/搜索/在线状态）
- 多人语音房间（DemoRoomPage：分享 URL、参与者面板、房间顶栏控制）
- 公开 Demo 页面（/demo 路由，自动 IM 连接，1v1 通话）

进行中：
- 完善评论高级能力（点赞、屏蔽、置顶）
- 补齐前端 Mobile 端 IM 功能
- 增加 E2E 测试和组件测试

### v0.4 后续版本

建议目标：
- 引入动态/帖子服务
- 引入群聊/频道能力
- 引入租户/项目最小模型（从 SaaS 蓝图落地）
- 统一错误码和 API 规范
- 开发者 SDK 和文档站
